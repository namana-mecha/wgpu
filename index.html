WGPU Rendering Pipeline Visualization

A high-level overview of the steps to render a triangle.

1. Initialization & Setup

Establish communication with the physical GPU and prepare the drawing surface.

Instance: Entry point to the WGPU API.
Adapter: Represents a physical GPU.
Device & Queue: Logical connection to the GPU for creating resources and submitting commands.
Surface: Links to the window where the final image will be displayed.

2. Prepare Resources

Allocate GPU memory for data and define the programs (shaders) that will run on the GPU.

Vertex Buffer: A buffer created on the GPU to hold vertex data (positions, colors, etc.).
Shaders (WGSL): Programs that run on the GPU.
  • Vertex Shader: Processes each vertex.
  • Fragment Shader: Determines the color of each pixel.

3. Define the Render Pipeline

Configure the GPU state. This object ties the data format, shaders, and render settings together.

Vertex State: How to read data from the vertex buffer.
Primitive State: How to assemble vertices (e.g., as triangles).
Fragment State: Configures the output color format.
Pipeline Layout: Describes the resources (like uniform buffers) the shaders will access.

4. Record GPU Commands

Record a sequence of commands into a command buffer. The GPU does not execute these immediately.

Command Encoder: The object used to record commands.
Begin Render Pass: Starts a block of drawing commands targeting a specific texture (the screen).
Set Pipeline & Buffers: Binds the pipeline and vertex buffer.
Draw Call: The actual command to draw the vertices (`draw(3, 1, 0, 0)`).
End Render Pass: Finishes the block of drawing commands.

5. Submit to GPU

Send the recorded commands to the GPU for execution and display the result.

Finish Encoding: Finalizes the command buffer.
Queue Submission: Submits the command buffer to the GPU's command queue.
Present: The final rendered image is displayed on the screen.
